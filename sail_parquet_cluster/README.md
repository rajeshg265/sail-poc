# sail_parquet_cluster — POC 6: Sail vs Spark on Parquet, local-cluster mode

## What this tests

Sail (pysail SparkConnect, `local-cluster`, 3 workers) vs Spark JVM
(`local-cluster[3,1,1024]`, 3 executors), both reading FRTB SA Capital data
from Parquet files. Same dataset as `sail_parquet` but with cluster mode enabled.

**Result:** Sail underperforms. `SELECT *` without column pruning (pysail 0.7.2
limitation) causes all 50+ columns to be transferred between workers via Arrow
Flight shuffle, amplifying the network cost in cluster mode even for
aggregation-only queries.

Data: 54.88M rows, ~9 GB — generated by `sail_parquet/infra/generate_data.py`.

## Prerequisites

| Dependency | Version |
|------------|---------|
| Python     | 3.13+   |
| pysail     | 0.7.2   |
| pyspark    | 4.2.0   |

Install Python dependencies:
```bash
pip install pysail==0.7.2 pyspark==4.2.0 pyarrow
```

## Setup

### 1. Generate data (if not already done)

This POC reads from the same `data/` directory as `sail_parquet`:

```bash
cd ../sail_parquet
python infra/generate_data.py
```

Or set `BENCHMARK_DATA_DIR` to point to an existing data directory:
```bash
export BENCHMARK_DATA_DIR=/path/to/your/data
```

### 2. Run the benchmark

```bash
python bench_cluster.py              # both Sail and Spark (10 runs each)
python bench_cluster.py --sail-only  # Sail only
python bench_cluster.py --spark-only # Spark only
```

Results are printed to stdout and saved to `results/results_<timestamp>.json`.

The benchmark runs 1 warmup + 10 timed runs per query, reports median and P99.

## Key files

| File | Purpose |
|------|---------|
| `bench_cluster.py` | Main benchmark: Sail local-cluster vs Spark local-cluster[3,1,1024] |
| `_bench_spark_worker.py` | Subprocess worker running the Spark side (avoids pysail/pyspark process conflict) |

## Known issues

- pysail 0.7.2 `SELECT *` (no column pruning): even `SELECT SUM(total)` internally
  reads all columns before applying the projection, causing excess Arrow Flight shuffle.
- `SPARK_LOCAL_IP=127.0.0.1` must be set for Spark local-cluster to bind correctly on macOS.
- Sail and Spark cannot share the same Python process — Spark subprocess worker
  (`_bench_spark_worker.py`) is used to avoid module-level state contamination.
